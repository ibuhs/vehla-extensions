# File Toolkit

Inspect, hash, and format files selected through Vehla’s native file picker.

This extension demonstrates:

- Single and multiple file form fields.
- File and folder selection.
- Allowed file-type filters.
- Selected-file metadata supplied by Vehla.
- Streaming file hashing.
- Bounded file reads.
- Structured native result views.
- Brokered clipboard and notification actions.

## Install

Install **File Toolkit** from Settings → Store.

For local development:

```sh
npm --prefix extensions/file-toolkit install --install-links
```

Then install `extensions/file-toolkit` as a local package.

## Commands

### Inspect Files

Keyword: `fileinspect`

Choose up to 15 files or folders. The result displays:

- Canonical path.
- File or folder kind.
- Content type when available.
- File size.
- Modification time.
- POSIX permissions.
- Folder entry count, capped at `10,000+`.

The **Copy Report** action copies a plain-text version through Vehla’s clipboard broker. Enable **Notify when complete** to request a macOS notification after inspection.

### Hash File

Keyword: `filehash`

Choose one file and select SHA-256 or SHA-512. The implementation hashes with a read stream rather than loading the entire file into memory.

This reference implementation rejects files larger than 500 MB so it can remain within Vehla’s command-time budget.

The result displays the digest and provides **Copy Digest**. The optional completion notification is delivered through Vehla rather than directly by the Node.js process.

### Format JSON File

Keyword: `jsonfile`

Choose a JSON file and select two- or four-space indentation.

The command:

1. Rejects directories.
2. Rejects files larger than 500 KB.
3. Reads UTF-8 text.
4. Parses JSON before formatting it.
5. Displays the formatted result without modifying the source file.

Use **Copy JSON** to copy the output.

## File form values

A single `file` field is delivered as:

```json
{
  "path": "/Users/example/input.json",
  "name": "input.json",
  "isDirectory": false,
  "size": 128,
  "contentType": "public.json"
}
```

A `files` field is an array of the same objects.

`size` and `contentType` are optional because folders and some filesystem objects do not provide them.

## Permissions

- `userSelectedFiles` — required before Vehla presents a command’s file picker.
- `clipboardWrite` — required only when a result’s copy action is selected.
- `notifications` — required only when a command returns a notification action.

Users can choose Allow Once, Always Allow, or Deny independently for each capability.

## Security boundary

Vehla shares only paths explicitly selected in the native form. File metadata is generated by the host before invocation.

The current JavaScript runtime is not sandboxed and runs under the user’s macOS account. File selection communicates intent and avoids accidental path entry, but it cannot prevent malicious Node.js code from accessing other user-readable paths. Install only trusted packages.

Recommended practices:

- Never silently modify selected files.
- Explain destructive behavior before submission.
- Bound reads and output sizes.
- Stream large inputs.
- Reject folders when a command expects a file.
- Do not persist selected paths unless the feature requires it.
- Treat filenames and paths as private user data.
- Use brokered actions instead of invoking system notification or clipboard tools.

## Test outside Vehla

The file form normally supplies metadata. It can be simulated:

```sh
printf '%s\n' \
  '{"jsonrpc":"2.0","id":"hash-test","method":"store.invoke","params":{"packageID":"com.vehla.examples.file-toolkit","commandID":"hash-file","query":"","context":{"formValues":{"file":{"path":"/absolute/path/to/file.txt","name":"file.txt","isDirectory":false},"algorithm":"sha256","notifyWhenComplete":false}}}}' \
  | node extensions/file-toolkit/index.js
```

Use a real absolute path and do not test with sensitive files.

For Store protocol and publishing details, see the repository-level README.
