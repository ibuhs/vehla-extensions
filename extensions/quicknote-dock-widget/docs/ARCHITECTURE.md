# Architecture and product study (2026-10-07)

Reviewed the complete VehlaDockWidgetSDK contract, SDK README/runtime matrix, Antinote plugin/model/editor/database/bridge/launcher/tests/build script, Research plugin/model/repository and Hertzly lifecycle. This checkout contains the public contract, not Vehla's host implementation. The linked upstream host example was unavailable through browsing; no private host API is assumed.

Store API 3 loads a signed bundle in Vehla. The protocol version is the SDK constant (currently 2), separate from manifest API 3. The principal class creates AppKit surface controllers containing transparent NSHostingViews for compact/inline/popup. The hosting view, scroll view, clip view and text view leave the host material visible. The hosting view is pinned to the host-sized container, with SwiftUI automatic sizing disabled; the native text editor does not supply a useful intrinsic height. A single plugin-owned observable model shares selection and library across controllers. Vehla owns window activation, geometry, permission grants, theme and invalidation. Theme callbacks update semantic colors; compact/inline use tileTextColor. There is no supported extension-owned global hotkey or custom host window API. Callbacks are synchronous MainActor notifications: schedule work, never wait for it.

The context supplies the package data directory and brokered copy/open/notify actions. The optional app bridge adds notes and starts host timers only for explicit user actions. Selecting/editing notes never publishes shared context or copies note text. Use these before inventing duplicate host infrastructure; old hosts retain local clipboard fallback. Filesystem/SQLite discovery, parsing, search, calculations, OCR and atomic persistence run on actors or cancellable worker tasks. AppKit text layout, pasteboard access, panels, focus, and host UI actions stay on MainActor. Hiding cancels visibility-specific jobs (AutoPaste keeps running, because copying happens in other apps and closes the popup); accepted saves drain asynchronously. Closing detaches context after scheduling the final save. Editor event monitors are scoped to their window, decline events for other text responders, and are removed on detachment/dismantling.

Existing Antinote was a companion, not a clone. No Import Notes button or independent importer existed in this folder. Its useful import infrastructure is QuickNoteDatabase.discover/best/locate/load: stable and Setapp containers, SQLite notes and Core Data ZNOTE schemas, UUID blob decoding, timestamp conversion, soft deletion filtering and checkbox markers. The new import path reuses these directly. It never invokes Accessibility, launches Antinote or writes its database. Installation detection and readable databases are separate: leftover databases can still be imported after uninstall. Known candidates are inspected even if directory enumeration is denied. Imported identities persist even in trash so reimport never overwrites local edits. Preview, selected import, manual SQLite backup/text/Markdown/widget JSON import, size bounds and cancellation extend the original parsers. Import failure never prevents the independent scratchpad from working.

Research sources: https://antinote.io/ , https://antinote.io/features , https://antinote.io/presskit (including Vendetta UI image), and user-manual pages navigation, slotted-notes, list, math, search, timer, autopaste, simple-markdown, find-and-replace, notes-management, export. Scratchpad emphasis: generous native plain-text editor, restrained chrome, keyword modes, compact status/results, no title form, lightweight search. Native AppKit slash completion and the /x list trigger reuse editor and model actions. Checkbox offsets are remapped during edits, then reconciled by the background parser without clearing every row. Navigation Cmd+[ / Cmd+], newest-front, promote, empty-note pruning. Permanent slots avoid expiry. Trash keeps deletion reversible. AutoPaste requires deliberate activation, reads the system pasteboard (Vehla's history records only with Clipboard Management on), skips concealed/transient copies and runs until turned off, the note changes or the widget closes. Timer ownership belongs to Vehla for countdowns so it survives popup closure.

Implemented scope and deliberate host adaptations are documented in README. Antinote's separate iCloud service, signed JavaScript marketplace, Vim engine and independent windows are not duplicated: these would require unrelated architectures and product infrastructure. No claim of binary/plugin compatibility with Antinote.


QuickNote 2.1.1 prepares the initially selected note on ScratchTools before publishing ready UI. Actor-produced presentation snapshots include exact source text, math results, checkbox ranges and Markdown spans. The model holds a bounded LRU projection keyed by note ID and validates exact source equality before reusing it; UI settings such as font/color are applied to cached spans at display time. Active-note prewarming runs at utility priority, yields between actor calls, skips trash, and stops on edits, navigation, hide or close. Foreground completion checks both selected ID and source text, preventing delayed work from replacing another note's presentation. The editor applies matching snapshots synchronously within its native view update. Persistence has no dependency on analysis and does not discard the cache. Bounds are 128 entries/16 MiB; warmup text is separately bounded to 8 MiB. This provides immediate revisits without unbounded startup parsing or memory growth.
