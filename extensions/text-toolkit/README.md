# Text Toolkit

A collection of practical text transformations for Vehla’s palette.

This extension demonstrates input fallback, validation, Unicode normalization, URL encoding, cryptographically random UUID generation, and date conversion using only Node.js standard APIs.

## Install

Install **Text Toolkit** from Settings → Store after refreshing the catalog.

For local development:

```sh
npm --prefix extensions/text-toolkit install --install-links
```

Then install `extensions/text-toolkit` as a local package.

## Input behavior

Commands that need text use this order:

1. Explicit palette query.
2. Selected text.
3. Clipboard text.

This makes both direct and context-driven workflows possible:

```text
slug Build Better Store Extensions
```

Or select text in another application, open Vehla, and choose **Create URL Slug** without typing an argument.

All successful command results are copied to the clipboard.

## Commands

### Format JSON

Keywords: `jsonfmt`, `formatjson`

```text
jsonfmt {"name":"Vehla","enabled":true,"commands":["one","two"]}
```

Output:

```json
{
  "name": "Vehla",
  "enabled": true,
  "commands": [
    "one",
    "two"
  ]
}
```

Invalid JSON returns a parsing error instead of copying partial output.

### Create URL Slug

Keywords: `slug`, `slugify`

```text
slug Crème Brûlée & Store Extensions
```

Output:

```text
creme-brulee-store-extensions
```

The implementation:

- Normalizes Unicode with NFKD.
- Removes combining accents.
- Converts to lowercase.
- Removes apostrophes.
- Replaces non-alphanumeric runs with `-`.
- Removes leading and trailing separators.

The slug alphabet is intentionally ASCII.

### URL Encode

Keyword: `urlencode`

```text
urlencode hello world & status=ready
```

Output:

```text
hello%20world%20%26%20status%3Dready
```

This uses JavaScript’s `encodeURIComponent`. It encodes a URL component, not an entire URL. Encoding a complete URL will also encode `:`, `/`, `?`, and `=`.

### URL Decode

Keyword: `urldecode`

```text
urldecode hello%20world%20%26%20status%3Dready
```

Output:

```text
hello world & status=ready
```

Malformed percent escapes are rejected with a clear error.

### Generate UUID

Keyword: `uuid`

```text
uuid
```

Output is a random RFC 4122 UUID generated by `node:crypto`:

```text
86b50595-f466-4ed4-aa6d-7be887901c11
```

This command ignores selected and clipboard text.

### Convert Timestamp

Keywords: `timestamp`, `unixtime`

Unix seconds to ISO 8601:

```text
timestamp 1784152800
```

Large numeric values with an absolute value of at least `100000000000` are interpreted as milliseconds.

Date string to Unix seconds:

```text
timestamp 2026-07-15T21:00:00Z
```

Output:

```text
1784152800
```

Date-string parsing follows JavaScript’s `Date.parse`; ISO 8601 with an explicit timezone is recommended.

## Permissions

- `clipboardRead` — enables clipboard fallback.
- `clipboardWrite` — copies command output.
- `selectedText` — enables selected-text fallback.

No data is sent over the network and no persistent data is stored.

## Implementation patterns

### Centralized input handling

`inputFor` keeps precedence consistent across commands. `requireInput` produces the same actionable error whenever required input is missing.

### Command-specific validation

Each operation validates at the narrowest useful point:

- JSON is parsed before formatting.
- Percent-encoded text is decoded inside `try`/`catch`.
- Numeric timestamps are checked for a valid date range.
- Date strings are rejected when `Date.parse` returns `NaN`.

### Dependency-free design

Everything uses built-in JavaScript and `node:crypto`, keeping installation small and reducing supply-chain exposure.

## Limitations

- JSON formatting does not preserve original key ordering beyond JavaScript object semantics.
- Slugification intentionally removes non-Latin characters after normalization.
- URL commands operate on components, not URL structure.
- Date parsing can vary for ambiguous, non-ISO strings.
- Very large input still counts against Vehla’s 1 MB response limit.

For advanced extension design and protocol details, see the repository-level README.
