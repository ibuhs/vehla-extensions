# Security Policy

## Supported Versions

Security updates are provided only for the latest stable release of the Vehla Extensions SDK.

| Version | Supported |
| ------- | --------- |
| Latest stable release | ✅ |
| Previous releases | ❌ |
| Development / pre-release builds | ❌ |

We strongly recommend updating to the latest SDK version before reporting a security issue, as the vulnerability may already have been resolved.

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, pull requests, or social media.**

Instead, report vulnerabilities privately by:

- Opening a **Private Vulnerability Report** through GitHub Security Advisories (if enabled for this repository).
- Emailing **kailaconsulting@outlook.comp**.

Please include as much information as possible:

- Description of the vulnerability
- Affected SDK version
- Steps to reproduce
- Proof of concept or sample code
- Expected vs. actual behavior
- Potential impact
- Any suggested mitigation

Please **do not include** real user data, API keys, access tokens, passwords, or other sensitive information in your report.

---

## Response Process

We aim to:

- Acknowledge reports within **3 business days**
- Validate and investigate the issue
- Keep you informed of progress
- Release a fix when appropriate
- Coordinate public disclosure after a fix is available

Response times may vary depending on the complexity and severity of the issue.

---

## Responsible Disclosure

We ask that you allow reasonable time for us to investigate and resolve reported vulnerabilities before publicly disclosing them.

Please do **not**:

- Access or modify data that does not belong to you
- Disrupt Vehla services or infrastructure
- Perform denial-of-service testing
- Attempt phishing or social engineering
- Retain or disclose sensitive information discovered during testing
- Exploit vulnerabilities beyond what is necessary to demonstrate their existence

We appreciate responsible, good-faith security research.

---

## Scope

This policy applies to the Vehla Extensions SDK repository, including:

- SDK APIs
- Extension loading and registration
- Permission and capability handling
- Extension-to-host communication
- Official example extensions
- Build and packaging configuration

Issues affecting only third-party dependencies should also be reported to the maintainers of those projects.

---

## Disclosure

Once a vulnerability has been fixed, we may publish a security advisory describing:

- Affected versions
- Impact
- Resolution
- Upgrade instructions

Researchers may be credited for their discovery unless they request to remain anonymous.

---

## Bug Bounty

Vehla does not currently operate a bug bounty program. We greatly appreciate responsible disclosure and security reports from the community.
